## 2024-05-24 - Resolve N+1 vulnerability using batched inArray and hash maps
**Learning:** Sequential database queries within loops like `Promise.all(arr.map(query))` can introduce a severe N+1 vulnerability affecting performance. By pulling out unique IDs and using `inArray` to fetch the data in a single batched query, and mapping the results with an O(N) hash map lookup, the system can scale much better. Also, always ensure required variables/imports like `inArray` are properly added.
**Action:** When mapping array of records and doing a DB query in the loop, use `inArray`, deduplicate IDs using `[...new Set(...)]`, query once, group in an in-memory Map structure for `O(1)` lookups, and assign back to the payload. When writing scripts to apply patches, use a completely new and unreserved file name (e.g. `_temp_patch.ts`), avoiding accidentally overwriting existing utility files in the workspace (e.g. `patch.ts` or `patch.sql`), then immediately delete it.
